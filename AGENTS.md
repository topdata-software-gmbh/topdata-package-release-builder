# AGENTS.md

`sw-build` is a single-package Python CLI that builds/packages Shopware 6 plugins. It runs from a
plugin checkout (or `--source-dir`), not from this repo. Entry point:
`topdata_package_release_builder.cli:main` -> `sw-build`.

## Commands

- `uv run --extra dev pytest` — full suite (~170 tests, real temp git repos).
- `uv run --extra dev pytest tests/test_free_branch.py::test_name` — focused test.
- `uv run --extra dev ruff check .` — lint. No CI exists, so run pytest + ruff before finishing.
- `uv run sw-build --help` / `uv run sw-build free status` — exercise the CLI locally.
- Install is editable (`uv pip install -e .`); `uv run` supplies the project and the dev extra.

## Behavior that will surprise you

- Config comes from **this repo's** `.env` (`config.PROJECT_ROOT = <package>/..`), not the plugin
  cwd. `RELEASE_DIR` is required unless `--output-dir`; real env vars win over `.env`.
- Interactive by default. `--version-increment {none,patch,minor,major}` skips the prompt. A
  non-`none` bump edits `composer.json`, then **commits, tags, and pushes the branch and tag to
  `origin`** (`workflow.py` + `git.py`). Don't do this in a scratch checkout.
- A dirty tree prompts to `git add .`; since everything is staged, the version-bump commit can
  include unrelated changes.
- Bare `sw-build <option>` is treated as `sw-build build <option>` by `DefaultGroup`; `-h/--help`
  still shows the group so the `free` subcommands are discoverable.
- Compiled assets are verified by SHA-256 content hashes, not mtimes. State lives in
  `.git/sw-build/<plugin>/.sw-build-assets.json`; the first run records a baseline and only a
  passing run updates it. `--rebaseline-assets` resets it; `--require-compiled-assets` makes
  missing output fatal.
- Free publishing is opt-in via committed `.topdata/build.yaml` (`free: {}` or `branch`/`zip` keys).
  It appends one commit to `origin/<branch>` (default `main-free`) without touching the checkout,
  requires a clean tree, ignores `--no-sync` for the branch, and only `--skip-free` bypasses it.

## Layout

- `cli.py` — Click group + build orchestration; `workflow.py` — versioning.
- `plugin.py` — composer metadata, payload copy/exclusions, ZIP; `assets.py` — asset verification.
- `variant.py` — rename/namespace transform; `foundation_injector.py` — foundation code injection.
- `free_manifest.py` / `free_branch.py` / `commands/free_cmd.py` — free-branch feature.
- `commands/self_upgrade_cmd.py` — `self-upgrade`: pull this checkout and refresh deps into the
  running interpreter (the `.venv` launcher from `scripts/install.sh`).
- `config.py`, `git.py`, `release.py`, `remote.py`, `slack.py`, `manual.py`, `pdf.py`, `tree.py`,
  `table.py`.
- `tests/conftest.py` builds `plugin_repo` / `foundation_plugin_repo` on real `git init` + a bare
  `origin`, so publication semantics are observable rather than mocked.

## Conventions

- Python floor is 3.10: PEP 604 unions (`str | None`) are evaluated at import time; use
  `from __future__ import annotations` when needed.
- The CLI uses `click` + `rich` + `InquirerPy`, not Typer, despite the generic recommendation in
  `ai_docs/CONVENTIONS-PYTHON.md`. Follow the code.
- Ruff is deliberately narrow (`E9`, `F`, `B`, ignoring `B008`); don't broaden it or reformat
  unrelated legacy modules.
- Release payload exclusions live in `copy_plugin_files` (`tests`, `.git*`, `builds`, `node_modules`,
  AI-tool files, ...). Add new tool directories there or they ship in the ZIP. `AGENTS.md` itself is
  excluded.
- `release_info.txt` must use `table_style="default"` (not `simple`): the consuming package-service
  regex only parses `Created`/`Branch`/`Commit ID` from that format.
- User-facing changes: update the paired `manual/*.de.md` + `*.en.md` and add a `CHANGELOG.md`
  Unreleased entry.
- Specs: active feature specs are `specs/NNN-<name>/spec.md`, registered in `specs/index.md`.
  `.specify/` is Speckit; its `constitution.md` is still the unfilled template.
- Plan/report artifacts go under `_ai/backlog/{active,archive,reports}`; `ai_docs/` is legacy.
